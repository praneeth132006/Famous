## The 10

### R1 · P1 Impossible demo · 18s
**Task:** photo of a handwritten timetable → importable calendar file.
**First frame:** the finished calendar, already filled in. Text: "this was a photo 20 seconds ago."
**Beats:** finished calendar (0–2s) → the crumpled handwritten paper (2–5s) → drop into the model (5–10s) → .ics file out, imported (10–16s) → loop back to calendar (16–18s).
**Send test:** sent to a classmate with "do this with our timetable."
**Caption:** Turn any handwritten schedule into a real calendar in one step. What else should I try this on?

### R2 · P3 One prompt · 15s
**Task:** the prompt that catches AI being confidently wrong.
**Prompt:** "Before you answer, list what you'd need to know to be sure. If you're missing any of it, ask me instead of guessing."
**First frame:** side-by-side, wrong answer vs the model asking a question. Text: "same question. one prompt different."
**Send test:** sent to anyone who has been burned by a hallucination.
**Caption:** Most wrong AI answers are a missing-context problem, not a model problem. Paste this before your next question.

### R3 · P2 Workflow teardown · 45s
**Task:** 2-hour lecture recording → structured notes + flashcards.
**Beats:** the finished flashcard deck (0–3s) → the raw 2h audio file (3–7s) → transcribe (7–15s) → notes prompt (15–28s) → flashcard export (28–40s) → deck again (40–45s).
**Send test:** sent to a study group during exam season. This one has the highest save ceiling in the batch.
**Caption:** Two hours of lecture to a finished flashcard deck. Full workflow, every step. Which subject should I run it on next?

### R4 · P4 Model vs model · 40s
**Task:** one real bug in real code, given to three models.
**Beats:** the bug revealed (0–3s) → "three models, same prompt, one is right" (3–6s) → each answer scored on screen (6–34s) → verdict (34–40s).
**Send test:** developers argue about this in group chats. Pure comment fuel.
**Caption:** Same bug, three models, one prompt. Only one of them actually read the stack trace. Which would you have trusted?

### R5 · P5 You're using it wrong · 20s
**Task:** pasting a screenshot of code instead of the file.
**First frame:** two answers side by side, one obviously better. Text: "same model. same question."
**Send test:** sent as a correction to a friend who does this.
**Caption:** A screenshot throws away every line number, every import, and the file tree. Attach the file.

### R6 · P1 Impossible demo · 22s
**Task:** messy Downloads folder → renamed and sorted by content, not filename.
**First frame:** the clean folder. Text: "342 files. I didn't touch any of them."
**Send test:** universally relatable pain. Very high send rate.
**Caption:** Sorted by what's inside the files, not what they're named. Script in the comments.

### R7 · P3 One prompt · 16s
**Task:** lecture PDF → 20 exam questions with an answer key.
**First frame:** the finished question paper. Text: "your own exam, from your own notes."
**Send test:** exam season, sent to the whole batch group.
**Caption:** Give it your actual syllabus PDF and ask for the paper your professor would set. Then mark yourself.

### R8 · P4 Model vs model · 38s
**Task:** same resume, three models, which output survives an ATS keyword scan.
**Send test:** anyone job-hunting sends this immediately.
**Caption:** Three rewrites of the same resume, scored against a real job description. The gap was bigger than I expected.

### R9 · P2 Workflow teardown · 48s
**Task:** a week of receipts → categorized expense sheet.
**Send test:** sent to whoever handles money in the house.
**Caption:** Photos of receipts to a finished spreadsheet, no typing. Every step shown.

### R10 · P5 You're using it wrong · 19s

18. "this is why your answers are worse"
19. "one file. no typing."
20. "I didn't believe this either"

**Hook rules:** under 8 words. No question marks in the first line (questions invite a scroll, statements invite a watch). No "POV." No "wait for it." Never name the tool in the hook — name the *result*.
